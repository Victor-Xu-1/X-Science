# Runtime · 任务运行

Runtime 将一次用户请求组织为模型交互、工具调用、验证和结果提交。
逻辑任务可以跨执行周期继续；单次模型、工具或进程操作仍有自身边界。
暂停、取消、进程退出和任务完成不是同一个状态。

## State and recovery · 状态与恢复

正常周期的阅读顺序为：

```text
claim → recovery → context → snapshot → provider ⇄ tool → verify → complete
```

这只是正常路径示意，不是完整枚举。验证可以要求继续模型修正；`paused`、`terminal`
及其他合法转换以 [machine.go](../../internal/sessionrunner/machine.go) 为准。
不要把阶段名直接当成用户可见的任务终态。

工具处理的顺序由 `NewPipeline` 检查。权限拒绝等提前结束路径仍需进入审计，
不能用新的 HTTP 路由或恢复回调绕开原有执行入口。详细不变量见
[Harness conformance](../engineering/x-science-harness-conformance.md) 和
[架构机器契约](../governance/harness-architecture.json)。

恢复会检查任务归属、执行身份和已有回执；可持久化的文件与检查点不等同于解释器内存快照。
进程已退出时不能仅凭最近心跳声称仍在运行。科学进程的创建、取消与资源约束见
[Science](science.md)，产物及事件提交见 [Evidence](evidence.md)。

上下文用量记录一次实际主模型请求，不是累计费用。服务商计数字段的缺失与明确的零
沿同一 JSON/流式回执区分；流式后续的部分计数不会清空早先已报告的字段。
只有完整有效的总量或输入/输出组成才标为供应商实测；仅有输出计数时保留实测输出和
原请求输入估算，总量仍标为估算。缓存是否另计由协议适配器声明，总量不重复加缓存。
这些遥测变化不改模型容量、压缩策略或任务执行权限，也不因指标写入失败重试模型副作用。

模型正文和工具提案继续严格解码。只有声明为可选的用量对象和缓存明细容器，才将合法
JSON 中非 null 的非对象值转为对应计数的固定类型异常；不保留原值，也不丢弃有效主结果。
缺失与 null 保持未知，不冒充实测零；损坏的缓存明细不抹除基础计数、独立总量或已知下界。
后续有效计数可以纠正当前异常状态，历史诊断仍保留；未知字段不能纠正先前的异常回执。
非法 JSON 和主协议字段错误仍失败。只含用量的流式帧不能充当模型生成或任务进展，
也不能绕过取消、响应字节预算或原有终态采纳边界。

自动软压缩的恢复状态绑定当前模型选择修订、公开模型身份及有效窗口策略。
同一绑定已经完成压缩、且没有新语义进展时，准备日志或新的租约领取不会重复压缩；
准备阶段与实际请求准入共享同一状态。更换模型、窗口策略或获得新进展后重新评估，
真实供应商拒绝和完整请求压力仍沿原有持久恢复路径处理，不被软预算跳过。
工具进展使用已提交的原批次、调用序号及终态关系，而不是可复用的调用 ID 或运行轮次。
新的批次可以在同一轮次复用 ID；旧结果的重复发布不能冒充新执行。缺少可靠来源的
历史回执保持未知，不能据此重跑工具或阻止请求。读侧关系不写回原事件，也不进入模型 JSON。

模型增强的 `Compact` 只从已识别的保留标记中采纳唯一、完整、非嵌套的摘要。
提取始终沿原字符串字节偏移，保留 Unicode 内容及无标记纯文本兼容；不完整或歧义
标记沿既有固定错误记录保留确定性摘要，不把原响应写入错误或公开交接，也不重复
请求模型或暂停任务。该边界不改变自动软压缩策略，也不补充先前摘要的公共内容连续性。

容量不足回执中的 `available_memory_bytes` 保留准入时同一次原始内存观测，
不从扣除控制预留后已归零的容量反推，也不为报告再次采样。实际准入继续使用
原有的预留扣减与持久资源预约；回执不会降低预算或把未启动计算标为已执行。

执行能力、引擎选择、Skill 加载及完成回执以当前持久化任务意图为边界。
纯“继续”命令和审批/询问回复保留原任务；带有新要求的后续请求使用自己的任务身份，
即使文字提到“继续”或上一轮产物，也不会自动继承旧阶段的执行限制。
历史消息、原文件和不可变产物版本仍可访问，不能冒充新请求已经执行。

界面的继续命令携带原始 `resume_target` 和稳定 `client_command_id`；受理回执、
已有恢复及可选唤醒沿同一事务提交。网络重试先返回原回执，不把旧命令重新绑定到
后续等待；纯后台 claim/requeue 不使同一语义目标失效。旧无条件 raw resume 接口
退役为 410。请求、busy/stale 边界及历史证据限制见 [Resume wake audit](../engineering/frame-resume-wake-audit.md)。

带工具的模型请求从派发起，按该调用配置的超时等待首次解码增长。请求头等待与
首次增长使用同一取消权威，避免等长定时器竞态导致传输重试。解码器接受正增长后，
原有语义空闲超时与有限响应字节预算接管本次生成；持续有效的私有推理或参数增长
不因尚无公开内容而被首次行动窗口中断，也不按公开回调重新开启该窗口。
合法事件先通过协议身份、字段及字节预算检查，再登记解码增长，最后调用公开呈现、
持久化或私有活动回调；消费方处理延迟不能消耗登记之前的首次增长窗口。
Responses 首次工具身份也属于有限计费的增长；完全相同的重复身份不续期，冲突身份
直接拒绝，工具参数仍须完整验证后才能执行。
Anthropic `signature_delta` 的不透明增量也按实际字节登记活动，沿原语义预算计费；
相同字节片段可再次出现，不将它猜成快照或身份重复。签名不进入公开或私有正文回调、
产物或持久消息，空字段、未知事件及其他协议字段不续期。
传输心跳、未成帧 JSON、重复终止标记和不再增长的参数快照不能续期；首个有效
终止状态只更新一次空闲观察，不能替代实际增长。
尚未收到响应头的超时仍是传输可用性失败，保留原有有界重试与失败语义，
不将它冒充已确认的模型无输出；收到响应后仍未形成可用动作才沿无输出恢复链处理。
已有解码增长但未完成公开答复或工具动作时，空闲或字节预算失败保留原始原因和
原生工具边界证明，沿同一有限生成恢复链保存检查点，不走传输层自动重放。
私有增长不增加持久任务进展或清空连续恢复计数；调用方取消仍优先。
可信工具 Schema 的 `durable-wait` 能力不受纯历史 exact-route 闭路限制：空等待仍不是
实际进展，也不重置故障预算，但后续持久通知到达时原生领取路径必须可用。
能力只取现有工具目录及其规范化元数据，不接受模型输入自报；参数、权限和其他
预检继续执行，普通计算、文件与来源动作的闭路不变。
恢复上下文沿同一能力权威只读投影当前仍闭路的动作，不向模型误报动态等待永久闭路；
原持久闭路回执、切片及连续计数保留，不以投影放宽执行权限。
已接受的正文按原续写回执保留，不增加生成的默认总时限或任务总时限，
也不缩短正在运行的科研进程。私有思考内容始终不进入公开消息。

首次公开进度只需说明眼前的行动及目的，不要求先完成整套工作计划、准备完整工具参数
或满足固定字数。公开块仍需完整、有效，经过原语言和内容边界后沿同一持久化链发布；
未确认角色的原生文字、私有推理和未完成工具参数不能提前展示或执行。
提示精简不保证服务商一定及时产出，应分别测量模型活动、公开块就绪、持久发布和页面显示。

未加载 Skill 时，MCP 上下文只提供获准连接器的发现提示，不复制全部延迟加载的方法名。
准确服务身份、方法及参数通过现有 `skill(filter)` 或 REPL 的 `host.mcp.list_servers()`、
`host.mcp.list_methods(server)` 按需获得；命名空间提示不能代替真实服务身份。
已加载 Skill 只保留仍获准的方法引用，发现和展示不扩大执行权限；执行仍由原有网关、
JSON Schema、审批和任务归属检查决定。

指定服务器的方法目录通过 `input_schema` 直接返回同一获准输入 Schema；
`input_schema_status` 区分 `complete`、`unavailable` 和 `projected_legacy`。
紧凑可迭代的 `parameters` 仍是便利视图，不是第二份完整 Schema 权威；旧目录的投影
不能冒充完整约束，新格式的值与状态不一致时明确报错。完整输入 Schema 沿既有分页、
受管大结果及摘要校验路径传递，不因单个 Schema 超过 64 KiB 而静默截断。

自动生成的工作计划是导航状态，不是第二套完成判据。最终答复通过任务契约、实际执行
回执和产物完整性检查后，未更新完的计划状态只记录为提示，不自动重开一轮模型调用、
重复计算或重新发布；原计划的待办状态保留，不能为了放行而伪造完成。
用户明确审阅并批准的执行计划仍保留原有执行义务，鉴权、归属和真实失败检查不变。
恢复入口使用同一完成策略：旧检查点的自动导航条件只有在持久化类型、当前任务及
计划版本完全匹配时才成为提示；不从说明文字猜测身份，也不清除其他计划或已批准的义务。

恢复阶段完成的内核调用和正常工具阶段沿同一持久化回执路径识别。阶段名用于观察，
不是执行是否发生的依据；非终态、未执行的前置拒绝和失败回执不能冒充成功。
计划状态反馈保留 `execution_ref`、`execution_binding` 和 `execution_continuation`，
模型可以复用匹配的已有执行，不得因为反馈压缩丢失标识而再次执行。
任务自由文本中出现工具名、重新分析、回读文件或报告失败代码，只产生可观察的线索，
不是受校验的操作授权或强制执行契约。线索与已有记录不一致时，最终答复保留真实原文，
在同一发布内容中附加一次中性未核实说明；不因此强迫调用、反复纠正或伪造成功回执。
旧语义审阅条件经普通续接重走当前机器检查，不直接结束任务、不把旧说明还原成答案。
内置附件读取器只提供可用性建议，不能因任务文字是否提到包管理器而改变操作准入。
实际工具协议、权限、当前输入/租约、活动执行、已批准计划和不可变产物检查仍保持独立；
只有真实成功的当前请求回执才可说明发生了新计算，历史结果不能冒充重新执行。

对应回归（含真实 SQLite、终态协议结算和可控 HTTP 模型边界）：

```sh

```

文本线索与真实执行权威的最小专项（不运行科研计算）：


## Focused verification · 验证入口

### Runner lease renewal · 运行租约续期

续期等待使用当前已经持有的租约剩余时间，不用更短的准备阶段窗口提前终止
正在运行的工作。调用方取消与已知租约到期仍是硬边界；取得数据库写锁后，
存储层再次校验身份、代次、输入版本与真实有效期。SQLite 暂时争用只经过现有
有限重试；未知存储错误、失权和真正过期不会被忽略，也不伪造续期成功。

```sh
go test ./internal/server -run 'TestRunnerLeaseRenewal|TestTranscriptRunnerHeartbeat|TestRunnerHeartbeatsStopCleanly' -count=1
```

### Background shutdown · 后台执行关闭

后台 Shell 的生命周期包括启动、进程退出、输出日志和任务终态持久化。
关闭服务时先封闭新启动的入口；已经获准、但尚未登记进程的启动也属于等待范围，
登记时发现关闭已开始就立即停止进程。只有全部收尾完成后，关闭才报告成功。
等待遵守调用方的取消和期限；日志或任务状态写入失败会明确记录并反馈，不以进程
消失或清空进程表代替成功收尾。
任务存储保留执行器的 `failed` 终态及退出码；普通命令失败不是关闭失败。
任务文件读写不占用启动/关闭互斥锁，文件系统阻塞时关闭仍能遵守调用方期限。

```sh
go test ./internal/server -run 'TestServerClose.*BackgroundShell|TestBackgroundShell' -count=1
```

### Provider generation recovery · 模型生成恢复

环境默认模型和已保存模型使用同一任务隔离的输出预算恢复逻辑。保存的单次输出额度
是初始软额度，不是整个任务后续生成的上限；显式调用级额度、任务级资源约束和供应商
确认的上限仍具有权威。配置和凭据不会因恢复而被改写。

流式请求因输出额度耗尽且没有原生公开文本或工具边界时，不反复从低软额度逐级重试：
恢复状态先持久登记一次供应商默认额度探测，再发起下一请求。探测在发送前原子消费，
重启或重复领取不能重复同一次探测；已有文字、不完整工具参数、取消和已知上限继续
遵守原边界。临时传输或额度错误仍保留真实用量与原有界协商；若默认探测始终没有
公开内容或工具边界，并以可信的初始无增长超时或已增长生成的空闲/字节边界结束，则撤销旧的
下一档数值回退，保留真实用量与供应商上限，不记录成功偏好、不猜测模型容量或关闭推理。

只有初始软额度的无输出截断随后经默认额度完整恢复成功，才记录同一所有者、模型配置、凭据引用及其非敏感版本、
协议、模型、角色和初始额度的请求偏好。任务首次自动额度协商时可优先采用这个已成功
的默认请求方式，避免再次从已失败的软额度起步。已开始的自动协商不被其他任务改写；
明确硬额度的调用不读取或初始化此偏好。凭据原位更新也会隔离旧偏好；无法确认凭据版本时
只保留任务内协商。偏好不包含提示词、凭据或任务上下文，也不共享任务的
上下限、用量和下一额度；配置变化隔离，硬调用额度仍先行。空结果、取消和截断工具
不能建立偏好；完整工具提案仍需原有执行权限和参数校验。该机制不保证模型一定产出
正文。持续私有推理仍受响应字节和语义空闲预算约束，不能冒充研究进展或完成。

显式额度不跳过恢复判定。生成失败的进展与重试条件使用同一个持久化检查点，
包括没有正文、工具参数尚未完整及模型返回空响应的路径。计数绑定当前输入和
提供方/模型/额度身份；真实新证据、有效输出或改变配置可以改变恢复决策，
准备日志和相同执行观察不能。输出截断或建议增大预算本身不是进展，不能绕过现有
连续无进展上限。初始增长定时器确认从未出现工具边界、也无公开正文的类型化超时空响应，
直接保存可恢复检查点并停止自动重放；已经出现但尚未完成的工具调用仍经过原有有界
恢复，不被混同为没有原生行动，也不获得执行残缺参数的权限。
已增长但仍无完成动作的空闲/字节失败沿既有连续生成恢复计数和退避处理，
私有字节不能重置该计数；达到既有上限后保存检查点并停止自动续跑。
普通空响应、响应头超时、暂时网络故障及已接受公开前缀继续遵守各自恢复语义。
手动继续或新的用户输入仍可重新发起请求，任务、已接受输出和产物不因停放而删除。
下一次生成的退避截止时间与观察一起持久化；普通运行池和恢复调度器均在请求前
遵守该截止时间，等待可取消，不会因重启或重新领取租约而跳过。

最终答复的语言判断与转写使用同一不可变字面量规则。结构化标识符、代码、链接、
文件名和数字不是英文叙述，不因缺少汉字而触发转写或新的模型轮次；普通英文句子
仍按当前任务的语言偏好尝试忠实转写，包括全大写句子。已有可用、非空主答复时，
后续语言转换失败、改变字面量或提出工具调用，不再丢弃原答复或重新执行任务；保留
精确原文并附加一次本地化说明，同时记录不含原文的失败类别审计。成功转换仍正常
交付；已有不可变字面量绑定路线最多执行一次，不因降级新增重试。已显示主答复前缀
后发生语言变化时，只追加说明，不替换或重复播放正文。两次辅助转换均与主请求的
上下文快照隔离，已知用量仍计入总量。空主答复、主模型失败、父请求取消及消息
发布或保存失败不适用这种呈现降级，仍由各自原有错误边界处理。
所有完成纠正的真实模型执行都进入原有
无进展观察，包括没有工具调用的视觉、引用及呈现修复：同一条件、同一恢复策略持续
无有效进展时，保存任务与检查点并进入可继续的暂停状态，不重复自动请求模型，也不
伪造完成或丢弃已接受输出。准备日志不会重置这一判断，健康工具和新证据不受影响。

续写回执始终保留已接受的精确文字。连续截断只增加少量字节时，这些字节不再单独证明
任务取得有效进展；原恢复链改为完成下一步动作，必要时把过大的单个动作拆开执行。
若供应商无法提供更大的有效额度，且改变生成方式后仍只产生碎片，保存原任务与检查点，
等待条件改变或用户继续；不把它标为任务完成或丢弃原消息。持续增长的输出、正在进行的
工具及长计算不受这条同路径恢复规则限制。

```sh
go test ./internal/server -run 'TestStaticOutputBudget|TestOutputBudget|TestContinuation.*Generations|TestContinuationGrowingBudget' -count=1
```

### First-response attribution · 首个输出归因

公开进度使用既有独立 envelope 协议，与工具参数和最终答案分开。完整块先经过统一
解码、语言与公开叙述检查，再走原持久发布边界；通过校验的块不等待整个工具响应
尾部。非公开正文仍是候选，工具仍须完整响应和原 admission；后续请求失败不把已
接受的进度冒充成成功。残缺或无效块不公开，不从未闭合工具 JSON 中截取字段。
语言转换仍在主请求完成后进行，不在流回调中递归启动第二个模型请求。新请求只
指导独立公开块，旧工具进度字段仅作兼容读取，不再注入或强制工具参数。

Chat-compatible 流也可在显式 assistant 角色、稳定响应身份及已广告函数提案
共同确认后，将当时的原生正文前缀交给同一公开块校验和持久链。这个边界只冻结
可见前缀，不宣称函数参数或整个响应已完成；后续合法正文、函数名碎片仍按原协议
解码，不因呈现优化新增失败门禁，也不扩充已接受的公开块。未知角色/身份、未闭合
控制或思考包装不提前展示。取消、语言顺序、完整工具准入和最终结算仍是原有权威；
恢复时精确前缀和有歧义的历史尾巴仍由原续写过滤器处理，不能借这个边界重复发布。
未获接受的早期观察不清空完整响应中的合法晚正文。原公开叙述过滤器按嵌套包装
移除完整或尚未关闭的私有思考段，保留真正可见的后缀和科学比较符；不只剥掉
未闭合包装的起始标签而留下其内容。

既有 communication audit 只记录请求级时间、计数和封闭来源，不保存正文、参数或私有
思考。`observer_request_started_at` 是观察层开始委托的时间；原生正文、原生工具边界、
完整响应、公开进度就绪、语言处理就绪和持久发布确认分别记录首次时间，未观察到的
阶段省略。它们不等于供应商首个网络字节、首次私有 token 或浏览器绘制时间。
私有活动另记录首次/末次回调时间和饱和的非负事件计数；未观察到时计数为零，时间省略。
事件数不是 token 数，也不证明整个时间区间持续有效；壁钟回拨保留原观测，不伪造连续时长。每次委托调用单独计量，包括失败
及辅助呈现请求，不保留推理内容、不改变进展窗口、重试或公开条件。
语言转写等辅助请求单独标记为 `presentation`，不能替换仍待公开的主请求时间范围。
这些观察不授权提前公开候选、改变工具权限或新增模型调用；公开块仍经过原语言、
真实性、去重及持久化边界。需要按同一请求比较到达与发布时间，不能把整段生成耗时
直接归因于缓冲。

临时模型服务或传输失败的自动重试原因由当前输入/运行代次的持久化事件投影到既有
frame runtime 快照。页面显示等待重试原因，不猜测供应商配额或倒计时；仅开始下一次
模型请求不代表恢复成功。真实公开/工具进展、终态、人工等待或新输入清理旧原因，
重连与实时更新使用同一权威。此展示不改变自动重试、租约、审批和取消策略。
等待用户继续的无公开输出暂停显示具体原因；首次请求也可形成暂停，界面及实时说明
不将它描述成已经连续恢复多次。未知原因使用中性暂停说明，不透传内部错误正文。

### Approval recovery and metrics · 审批恢复与统计

批量调用的执行前拒绝事实属于宿主权威，随原始调用检查点保留；供应商参数不能设置
这个标记。审批恢复必须核对原始调用、参数、所有者及当前分支，保持已完成回执不重跑，
把被拒绝的后续调用交还为未执行的纠正反馈，不能因为没有执行记录就重新放行。
正常获准调用仍必须具备匹配的执行记录。旧版终态清理留下的不确定回执，只有在原始
拒绝事实明确、没有开始/等待、操作或执行证据时，才在只读模型回放中表达为未执行；
原审计与终态批次不改写、不重开，真正不确定的执行结果不作推断。

最新一轮的模型与工具统计使用同一已捕获运行轮次集合。审批回复推进输入版本时，
该轮已准入的根工具批次仍计入；同一批次的重放和嵌套生命周期事件不重复计数。
真正的新用户输入仍与前一轮区分，工具统计不会再次读取可变版本而与模型统计错位。

### Reading progress · 读取进展

任务内重复读取相同来源和窗口时，以实际返回内容判断是否有新证据，不以模型附带的
说明文字或新的工具调用编号判断进展。普通文件每次仍通过原权限检查并读取当前内容；
相同窗口内容未变才返回复用标记，文件变化和后续窗口继续正常执行。
观察摘要随已完成回执恢复，且使用任务内有界缓存，不跨项目或任务共享。
同一末页的等价窗口不会因为请求了更多行而被当成新证据。
恢复从活动分支的权威事件流重建观察，不复用为模型裁剪的最近消息窗口；
准备日志不能把已读取的证据变成首次读取。解释器的重复可观察结果仅用于恢复
进展判断，不缓存执行，也不声称未知外部副作用已经被证明不存在。

受信只读 MCP 的来源观察使用原有主机证明、实际输入和完整原始结果摘要，不把 REPL
代码、打印标签或执行 ID 当作来源内容。实时完成与重启恢复沿同一 canonical 分支、
所有者和输入版本重建观察；大结果必须通过既有原文归属、版本、大小和摘要校验，
不可验证时为 unknown，不以预览或 descriptor 代替原文。来源窗口只比较最近 256 个
已验证身份；每个操作和同时待完成操作都有界，观察不完整时不声称全部重复。

持续返回同一已验证来源时，模型先获得复用来源或改变下一步行动的反馈，再沿既有
有界恢复链纠偏。来源模式明确保留未知解释器副作用与未仪器化新计算的可能性，
不会把外层代码加入可跳过/封闭动作，也不缓存或取消已授权调用。真正的新来源、
文件、产物或已有可信 changed-effect 计算回执仍构成进展；没有文件的计算也不例外。
来源纠偏可能在混合或未知 cell 已完成后暂停继续生成，这不是任意代码“没有新计算”
的证明。原始结果和恢复点保留，改变行动或显式继续仍使用原权限与执行链。

来源观察的输入边界取自当前 canonical 分支上真实入场的用户消息/输入回复及其工具
proposal 事件，不从当前 attempt 行反推历史版本，也不从任务文本猜测。晚到的旧
operation 即使复用相同 call ID，仍须匹配不可变 proposal 坐标；无法证明归属则 unknown。
来源模式使用现有恢复 schema 的可选严格字段，不增加全局恢复合同 revision 或改变
暂停任务的自动恢复条件。回滚到旧 reader 时，含新字段的派生状态会被严格解析拒绝，
旧版不具备新模式语义；原始 canonical 回执、结果和暂停点保留，不以回滚自动重跑任务。

缓存来源与文件读取的混合批次沿原无进展恢复链处理：模型先获得复用已有证据、改变
下一步动作的反馈；持续重复则保存恢复点，不重复网络副作用，也不靠固定任务时长终止
健康下载或计算。大结果仍遵守原有不可变回执与读取权限，不能将预览当作全文。

```sh
go test -race ./internal/server -run 'TestReadProgress|TestSessionRunnerReadReuse|TestServerAgentRuntimeReadReuse|TestCorrectionRead|TestCorrectionPaged|TestNoProgressReceipt' -count=1
```

从仓库根目录执行：

```sh
go test ./internal/sessionrunner ./internal/toolgateway -count=1
```

这验证阶段转换和工具顺序，包括架构契约一致性；它不覆盖所有 server 恢复适配器，
也不是一次真实模型任务。修改恢复、取消或完成逻辑时，继续选择
`internal/server` 下直接相关的回归，再用实际模型或工具协议复测同一行为。
凭据、网络或运行环境不可用时，应分别记录，不能用模拟响应宣称真实链路通过。

### Durable active-work clock

任务累计与最新输入的耗时共用 Transcript 的租约区间归约器，在同一只读 SQL 快照中
读取 attempt、当前输入版本及 canonical 计时事实。原始 `claimed_at` 和真实终结审计时间
不改写；每段运行到已记录的租约端点或更早的终结/观测时间为止。成功的同 attempt
checkpoint 恢复在原 claim 事务中追加内部 `runner_timing_resumed` 事实，精确绑定
所有者、stream、attempt、前后输入版本、前后 claim generation、旧租约结束及新 claim
开始时间。失败/重复 claim 和续租不创建新的恢复区间，未成功取得 runner 的 dispatch
轮询也不形成计时事实。不同输入按各段不可变版本归属，不从被更新的 attempt 行反推。
这只是可验证的 runner 活跃区间与任务累计时钟；租约端点不是科研任务总时限，不会
终止 detached 或远程长计算，也不能替代 kernel、作业调度器或科研执行回执。

该事实没有 delivery destination，不是用户输入、模型上下文、工具/科研执行回执或唤醒
条件。公共历史与增量游标共用内部事实过滤器；即使只含内部事实的一页也推进来源游标，
不制造消息或工具状态。查询沿既有 `(stream_uid, client_message_id)` 索引的事实前缀范围，
不会为了每次计时读取扫描长任务的全部工具结果。没有新表、迁移或第二套时钟权威。

历史同 attempt 恢复未记录精确端点、generation 链断裂或原始事实不属于当前所有者/
stream 时，受影响的累计耗时明确不可用，不按壁钟猜测、不回填暂停区间，也不发布假的
零。之后独立新输入的完整区间仍可单独准确计量，不能冒充完整任务累计。API 的
`runtime_elapsed_available` 与 `runtime_task_elapsed_available` 分别约束相应数字；
不可用时数字为 null，前端不能退回缓存值或 started-at 壁钟推算。兼容投影不再重复扣除
已经由租约端点排除的暂停时间。回滚到不理解该事实的旧计时 reader 不保留新计时语义；
需保留兼容 reader 与原始事实，旧二进制漏记的新 generation 会被识别为 unknown，
而不是因此自动重跑或修改用户任务。

壁钟回拨、无效时间端点或计时溢出只使对应耗时 unavailable，并保留非致命的原始
`ObservationError` 与 canonical 数据，不使对话因单纯计时未知而不可读取，也不改变
执行状态或恢复条件。所有者、SQL/schema 与请求取消错误仍沿原错误通道返回。

暂停投影读取真实恢复权限，不读取计时是否可用。普通非自动恢复的 interruption 只有在
匹配的 resumable checkpoint 存在时才显示可继续暂停；不可恢复的过期边界仍走原执行
停滞提示。模型选择保留既有 fresh-input 恢复例外，自动恢复的兼容分支不变。
